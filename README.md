# icloud-cli

A Go CLI to interact with iCloud services directly from your terminal: **calendar and event** management via CalDAV, **email** management (read, send, search, drafts, folders) via IMAP/SMTP, and **Reminders** (macOS only — list, search, create, update, complete) via Apple's EventKit framework.

The tool talks **exclusively to Apple servers** (`caldav.icloud.com`, `imap.mail.me.com`, `smtp.mail.me.com`) over encrypted connections (TLS/STARTTLS). On macOS, Reminders go through the system `remindd` daemon, which syncs with Apple's iCloud CloudKit container. No telemetry, no analytics, no third-party update checks.

> Fork of [`jingkaihe/icloud-cli`](https://github.com/jingkaihe/icloud-cli).

## Requirements

- Go 1.25+ (only needed to build from source)
- An Apple ID with two-factor authentication enabled
- An **app-specific password** (see below)

## ⚠️ iCloud app-specific password (required)

Apple **does not allow** you to use your main Apple ID password to access CalDAV, IMAP and SMTP from third-party clients. You must create an *app-specific password*.

**Why it's required:**
- Apple's two-factor authentication blocks direct login with the main password on the IMAP/SMTP/CalDAV protocols.
- An app-specific password is generated by Apple, scoped to that client only, and **does not grant access to the rest of the account** (it can't make App Store purchases, can't read iCloud Keychain, etc.).
- It can be revoked at any time from your Apple ID settings without changing your main password.

**How to generate one:**

1. Go to [account.apple.com](https://account.apple.com) and sign in with your Apple ID.
2. Under **Sign-In and Security**, find **App-Specific Passwords**.
3. Click **Generate Password** and give it an identifying label (e.g. `icloud-cli`).
4. Apple will show a password in the format `xxxx-xxxx-xxxx-xxxx`: **copy it immediately** — it won't be shown again.
5. Use this password when `icloud account add` asks for `APPLE_APP_SPECIFIC_PASSWORD`.

**Apple-imposed limits:**
- Maximum **25 active app-specific passwords** per Apple ID.
- If you change your main Apple ID password, **all app-specific passwords are revoked** and must be regenerated.
- Two-factor authentication on your Apple ID **must be enabled**, otherwise Apple will not allow you to create app-specific passwords.

## Installation

### From source

```bash
git clone https://github.com/emmekappa/icloud-cli.git
cd icloud-cli
go build -o icloud .
# optional
sudo mv icloud /usr/local/bin/
```

### Verify

```bash
icloud version
```

## Account setup

The first step after installation is to register your iCloud account:

```bash
icloud account add \
  -e your.name@icloud.com \
  -p xxxx-xxxx-xxxx-xxxx \
  --alias personal
```

Or via environment variables (useful for scripts / CI):

```bash
export APPLE_EMAIL=your.name@icloud.com
export APPLE_APP_SPECIFIC_PASSWORD=xxxx-xxxx-xxxx-xxxx
icloud account add --alias personal
```

Multiple accounts are supported side-by-side — select one on any command with `-a <alias>`, or set a default:

```bash
icloud account list
icloud account set-default personal
icloud account remove old-alias
```

> Note: `@icloud.com`, `@me.com` and `@mac.com` are all valid Apple domains.

## Commands

### Account

```bash
icloud account add [-e EMAIL] [-p PASSWORD] [-n NAME] [--alias ALIAS]
icloud account list
icloud account set-default <alias>
icloud account remove <alias>
```

### Calendars

```bash
icloud calendar list [-a ACCOUNT]
icloud calendar create <name> [-a ACCOUNT]
icloud calendar update <calendar-id> -n <new-name> [-a ACCOUNT]
icloud calendar delete <calendar-id> [-a ACCOUNT]
```

### Events

```bash
# List events (defaults to current week)
icloud event list [-a ACCOUNT] [-s START] [-e END] [-c CALENDAR_ID] [-o tsv|json]
  # Dates: YYYY-MM-DD or relative (1d, 1w, -2d, 1m)

# Event details
icloud event get <event-uid> -c CALENDAR_ID [-a ACCOUNT] [-o tsv|json]

# Create
icloud event create -t TITLE -s START -c CALENDAR_ID \
  [-e END] [-l LOCATION] [-d DESCRIPTION] [-r RRULE] [-a ACCOUNT]
  # START/END: "YYYY-MM-DD HH:MM" or "YYYY-MM-DDTHH:MM"
  # END defaults to 1 hour after START

# Update
icloud event update <event-uid> -c CALENDAR_ID \
  [-t TITLE] [-s START] [-e END] [-l LOCATION] [-d DESCRIPTION] [-r RRULE] \
  [-S | -o YYYY-MM-DD HH:MM] [-a ACCOUNT]

# Delete
icloud event delete <event-uid> -c CALENDAR_ID \
  [-S | -o YYYY-MM-DD HH:MM] [-a ACCOUNT]
```

Recurrence rules (`-r` / `--rrule`):

| RRULE | Meaning |
|---|---|
| `FREQ=DAILY` | every day |
| `FREQ=WEEKLY;BYDAY=MO,WE,FR` | Mon / Wed / Fri |
| `FREQ=WEEKLY;INTERVAL=2` | every 2 weeks |
| `FREQ=MONTHLY;BYMONTHDAY=15` | 15th of every month |
| `FREQ=DAILY;COUNT=10` | 10 occurrences |
| `FREQ=WEEKLY;UNTIL=20251231T235959Z` | weekly until end of 2025 |

For recurring events, `update` and `delete` accept:
- `--series` / `-S` → modify/delete the entire series
- `--occurrence` / `-o "YYYY-MM-DD HH:MM"` → act on a single occurrence

### Email

```bash
# Mailboxes
icloud email mailbox list [-a ACCOUNT]

# List messages
icloud email list [-m MAILBOX] [-n LIMIT] [-o tsv|json] [-a ACCOUNT]
  # MAILBOX: INBOX (default), "Sent Messages", Drafts, Trash, Junk, Archive

# Read a message
# Attachments are saved to ~/.cache/icloud/attachments/<mailbox>/<uid>/
icloud email get <uid> -m MAILBOX [-a ACCOUNT] [-o tsv|json]

# Search (IMAP syntax)
icloud email search "FROM:alice@example.com UNSEEN"
icloud email search "SUBJECT:invoice SINCE:2025-01-01"
icloud email search "BODY:meeting"
  # Criteria: FROM:, TO:, SUBJECT:, BODY:, SINCE:, BEFORE:, UNSEEN, FLAGGED

# Send
icloud email send -t TO -s SUBJECT [-c CC] [-b BCC] [-B BODY] [-f FILE] [-a ACCOUNT]
  # TO/CC/BCC: comma-separated addresses
  # -B inline text, -f reads the body from a file (.txt or .html)

# Reply
icloud email reply <uid> -m MAILBOX [-B BODY] [-f FILE] [--all] [-a ACCOUNT]
  # --all: reply to all recipients

# Manage
icloud email move <uid> -m SOURCE -d DESTINATION [-a ACCOUNT]
icloud email delete <uid> -m MAILBOX [-f] [-a ACCOUNT]
icloud email mark <uid> -m MAILBOX --read|--unread [-a ACCOUNT]
icloud email flag <uid> -m MAILBOX --set|--unset [-a ACCOUNT]
```

### Drafts

```bash
icloud email draft create -t TO -s SUBJECT [-c CC] [-B BODY] [-a ACCOUNT]
icloud email draft list [-n LIMIT] [-o tsv|json] [-a ACCOUNT]
icloud email draft get <uid> [-o tsv|json] [-a ACCOUNT]
icloud email draft update <uid> [-t TO] [-s SUBJECT] [-c CC] [-B BODY] [-a ACCOUNT]
icloud email draft delete <uid> [-f] [-a ACCOUNT]
icloud email draft send <uid> [-a ACCOUNT]
```

### Reminders (macOS only)

> **Platform:** macOS only. The `reminder` commands are stubbed out on Linux and Windows and will return an "unsupported platform" error.
>
> **Build requirement:** CGO must be enabled. `mise run build` and `go build` (both run natively on macOS) enable it by default. The pre-built release binaries are cross-compiled with `CGO_ENABLED=0`, so to use the Reminders commands you currently need to build locally on a Mac.

#### Why Reminders are different

Apple **does not expose modern iCloud Reminders via CalDAV**. Starting with iOS 13 (September 2019), Reminders were migrated to a private CloudKit container; the legacy CalDAV VTODO lists were frozen and now only contain two migration placeholders ("Where are my reminders? / The list owner has upgraded reminders."). See [Apple KB HT210220](https://support.apple.com/HT210220).

The only ways to access the real Reminders are:
1. Apple's private iCloud web API — requires full Apple ID login with interactive 2FA (app-specific passwords don't work), reverse-engineered, unstable.
2. Apple's **EventKit** framework — public, documented, stable — **macOS only**.

This tool uses option 2. Reminders flow through the local `remindd` daemon, which is already authenticated with your iCloud session at the system level. No credentials are stored or passed in — app-specific passwords are **not** used for Reminders.

#### First-run permission

On first use, macOS will show a TCC prompt asking you to authorize your terminal (Terminal.app, iTerm, Ghostty, …) to access your Reminders. You can revoke it any time from **System Settings → Privacy & Security → Reminders**.

If a prompt never appears and you get a permission error, run once interactively from a GUI terminal — macOS will not show TCC prompts for processes launched outside a user session (e.g. from `launchd` without `AssociatedBundleIdentifiers`).

#### Commands

```bash
# Read
icloud reminder lists [-o tsv|json]
icloud reminder list [-L LIST_ID] [-n LIMIT] [--include-completed] [-o tsv|json]
icloud reminder get <uid> [-o text|json]

# Search (client-side filter; composes text + structured filters)
icloud reminder search [query...] [-L LIST_ID] [--include-completed]
                                  [-p none|high|medium|low]
                                  [--due-before YYYY-MM-DD]
                                  [--due-after YYYY-MM-DD]
                                  [--no-due] [-n LIMIT] [-o tsv|json]
  # [query...] is matched case-insensitively in title + notes (AND across terms).
  # With no query, only the structured filters apply.
  # Examples:
  #   icloud reminder search milk organic
  #   icloud reminder search -p high --include-completed
  #   icloud reminder search --due-before 2026-12-31
  #   icloud reminder search anagrafe -L "8C8FC09C-..."

# Write
icloud reminder create -t TITLE [-L LIST_ID] [-d DUE] [-p PRIORITY] [-n NOTES] [-u URL]
  # DUE: YYYY-MM-DD (all-day) or "YYYY-MM-DD HH:MM" (timed; also sets an alarm)
  # PRIORITY: none | high | medium | low (or 0-9 per RFC 5545)
  # LIST_ID defaults to the system "Default List" for new reminders

icloud reminder update <uid> [-t TITLE] [-L LIST_ID] [-d DUE] [-p PRIORITY] [-n NOTES] [-u URL] [--clear-due]
  # Only the flags you pass are changed.
  # Pass --clear-due to remove the due date (and its alarm).
  # Pass -n "" or -u "" to clear notes / url.

icloud reminder complete <uid>
icloud reminder uncomplete <uid>
```

Example:

```bash
$ icloud reminder lists
ID                                      TITLE      SOURCE  COLOR    DEFAULT  WRITABLE
751F121D-...                            Casa       iCloud  #B14BC9  *        yes
2255CF62-...                            Spesa      iCloud  #5AC8FA           yes
...

$ icloud reminder list -n 5
UID         LIST    DONE  PRIORITY  DUE         TITLE
2AC4365A-…  Casa         none                   Scegliere lampadari
1740A94C-…  Fiscali      none      2026-11-10   Versamento fondo pensione
...
```

The JSON output exposes every field EventKit makes available: `uid`, `title`, `notes`, `url`, `list`, `list_id`, `completed`, `completed_at`, `priority` (0 none, 1 high, 5 medium, 9 low — RFC 5545 convention), `due` / `due_has_time`, `created_at`, `modified_at`, and an `alarms` array with both absolute and relative offsets.

#### Known limitations

- **Tags** (iOS 15+ `#tag` chips) are not exposed as a separate field by EventKit — they appear inline inside the reminder title string and are preserved verbatim on write.
- **Nested subtasks** (iOS 14+) are not exposed as a structured tree by the public EventKit API; they surface as sibling reminders on the same list.
- **Smart lists** (Today, Scheduled, Flagged, All) are virtual — they are not returned by `reminder lists`. Filtering equivalents can be built on top of `reminder list --include-completed -o json` with client-side logic.
- **Alarms**: `create` and `update` install a single absolute alarm at the due datetime when a time is given, mirroring what the Reminders app does. Custom relative alarms (e.g. "30 min before") are shown by `get` but not yet settable from the CLI.
- **Delete** is not implemented yet — use the Reminders app to delete for now.

## Configuration and environment variables

| Key | Description |
|---|---|
| `~/.config/icloud-cli/config.json` | Configuration file (accounts and aliases) |
| `~/.cache/icloud/attachments/` | Local cache for downloaded email attachments |
| `APPLE_EMAIL` | iCloud account email (env override) |
| `APPLE_APP_SPECIFIC_PASSWORD` | App-specific password generated on account.apple.com |

The `config.json` file stores credentials **in plaintext**: its protection relies on your user's filesystem permissions. This is one more reason to use an app-specific password (revocable) instead of your main Apple ID password.

## Network endpoints

The only hosts contacted by the tool:

| Service | Host | Port | Encryption |
|---|---|---|---|
| CalDAV | `caldav.icloud.com` | 443 | HTTPS |
| IMAP | `imap.mail.me.com` | 993 | TLS |
| SMTP | `smtp.mail.me.com` | 587 | STARTTLS |

Usernames:
- **IMAP**: the email prefix (e.g. `alice` for `alice@icloud.com`)
- **SMTP** and **CalDAV**: the full email address

**Reminders (macOS only)** do not hit any of these endpoints directly. They go through the local `remindd` daemon using Apple's EventKit framework — which in turn syncs with iCloud via Apple's internal CloudKit container. No iCloud credentials pass through this tool for Reminders.

## Privacy and security

- **No third-party servers**: the tool does not send data to analytics, telemetry, crash reporters, or external update checkers.
- **TLS everywhere**: all connections are encrypted.
- **App-specific password**: see the dedicated section above. Never use your main Apple ID password.
- **Local credentials**: stored in `~/.config/icloud-cli/config.json`. You can also skip storage and pass them every time via `APPLE_EMAIL` / `APPLE_APP_SPECIFIC_PASSWORD`.
- **Quick revocation**: if in doubt, revoke the app-specific password on [account.apple.com](https://account.apple.com) — it's immediate and does not affect your main Apple ID password.

## Development

```bash
# Build
go build -o icloud .

# Unit tests
go test ./...

# Acceptance tests (require a configured iCloud account)
go test -v -tags=acceptance ./test/acceptance/...

# Tidy dependencies
go mod tidy
```

Stack:
- [cobra](https://github.com/spf13/cobra) — CLI framework
- [emersion/go-webdav](https://github.com/emersion/go-webdav) — CalDAV client
- [emersion/go-imap/v2](https://github.com/emersion/go-imap) — IMAP client
- [emersion/go-smtp](https://github.com/emersion/go-smtp) — SMTP client
- [emersion/go-message](https://github.com/emersion/go-message) — MIME parsing
- [teambition/rrule-go](https://github.com/teambition/rrule-go) — iCalendar recurrences
- [google/uuid](https://github.com/google/uuid) — UID generation
- Apple EventKit framework via a small Objective-C bridge (CGO, darwin-only) for Reminders

The Reminders integration lives in `internal/reminders/` and is gated by build tags (`darwin && cgo`). On any other platform (or with `CGO_ENABLED=0`), a stub implementation is compiled in its place — the `icloud reminder …` commands will still exist but return a clear "unsupported platform" error.
